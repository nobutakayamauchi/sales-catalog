LLM COST ROUTER / RESEARCH EDITION

AIに、考えさせすぎていないか。

推論を安くするだけではない。
どこで時間・Context・Retry・Computeが溶けているかを見つけ、成果につながる場所へ資源を寄せる。

LLM Cost Routerは、CodexなどのAIコーディングエージェントを計測し、無駄の急所を見つけるためのResearch Editionです。標準Runtimeは制作者自身が研究・実運用で使うReference Runtimeを基準に提供します。

PROBLEM

上限に当たる前に、どこで燃えているかを知る。

AI開発では、単純なモデル単価だけでは見えない浪費が積み上がります。

Contextの再取得

同じrepo、同じ仕様、同じログを何度も読み直していないか。

失敗Retry

環境が動かない、Buildが通らない、同じ探索を繰り返す。その消費は成果になっているか。

過剰な推論

強い推論が本当に必要な場所と、決定論的なToolで済む場所を分けられているか。

Compute配置

低スペックHostで巨大Buildを回すなど、処理場所そのものが間違っていないか。

無進捗の長時間実行

Agentが生きているだけで、Accepted Resultへ近づいていない時間を観測できるか。

成果ゼロの消費

Tokenが減ったかではなく、その消費で最終成果がAcceptedされたかを評価します。

DOGFOOD / BASELINE

最適化を意識していた環境でも、これだけ燃えた。

1 task / 約30分 / cumulative input 8,143,782 / final acceptance FAIL

初期DogfoodのRouter OFF基準では、累積input 8,143,782 tokensのうち7,904,000がcached inputでした。これは「814万の新品Tokenを一度に課金された」という意味ではありません。それでも約30分動作し、最終AcceptanceはFAILでした。

これは単一の個別実験です。一般的な削減率や成功率改善を保証するものではありません。現在、Router ON/OFFの比較研究と外部環境での再現性検証を進めています。

WHAT IT DOES

急所を決め打ちしない。

「Reasoningを下げれば終わり」ではなく、実際にどこで浪費しているかを観測して必要な制御だけを使います。

Capability Preflight

大きなContextや推論を投入する前に、そもそも実行可能な環境かを確認。

Context / Tool Routing

必要なContextだけを渡し、機械で済む処理をLLMへ考えさせない。

Reasoning Routing

タスクの難度・リスクに応じて推論資源を配分。

Compute Routing

Local、Codex、CI/Remoteなど、仕事に合う実行場所へ振り分ける。

Budget Observer

経過時間、Command、Failure、Repeat、進捗などを観測。

Acceptance Gate

安く終わっただけでは成功にしない。Accepted Resultを最終評価軸にする。

FAQ

よくある確認

Tokenを必ず何％減らせますか？

保証しません。急所は環境ごとに異なります。再現性のある研究結果が揃うまでは平均削減率を販売主張に使いません。

Personalを会社で使えますか？

会社・法人を代表して業務利用する場合はBusiness Licenseが必要です。

購入すれば個別最適化も全部やってもらえますか？

標準Runtimeの提供が基本です。個別診断や専用カスタマイズは別料金です。

研究に協力したい場合は？

AIコーディングを大量に利用している方の実環境データを募集予定です。公開する場合は個別の研究条件とデータ取扱いを別途明示します。
